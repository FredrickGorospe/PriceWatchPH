# TASK_005 — Provenance fields, payload retention, and seller pseudonymisation

## 1. Scope

Goal: the schema and the write-path primitives that TASK_006/007 need in order to
write `personal_records` and `manual_capture` data **safely and once**, since
`RawListing` rows can never be corrected afterwards. Three things land together
because they are one decision each about what an immutable row must carry:

- **Provenance in time** — `RawListing.occurred_at` (when the priced event
  actually happened, per the source) distinct from `fetched_at` (when this system
  learned it), and `Listing.observed_at` as the single timestamp phase 5 buckets
  on, so the pricing engine never reads `RawListing`.
- **Re-derivability** — `RawListing.payload`, the verbatim source row, so a
  source-stated fact this schema did not anticipate is recoverable rather than
  lost.
- **Pseudonymisation** — counterparty names replaced by a keyed HMAC token
  before write, in both the `seller` column and the payload, so no plaintext name
  ever enters a table that cannot be redacted.

This is a **new migration on top of shipped work**, not a correction to
TASK_003/TASK_004. Their models, migrations, and tests are not reopened.

**Out of scope for this task** — do not touch, do not scaffold, do not
anticipate:

- Any importer (`manual_capture`, `personal_records`), the `ingest` management
  command, or any code that actually writes a `RawListing` row — TASK_006/007.
- Any aggregation: computing a median, a `PricePoint`, or a rolling baseline.
  This task delivers the *day-bucketing primitive* and nothing that calls it in
  anger — phase 5.
- Any resolver: nothing populates `Listing.observed_at`, `price_kind`, or
  `trade_side` in this task. The columns exist; phase 3 fills them.
- `Source.is_active`, DRF, the scheduler, the admin beyond what already exists.
- Editing `TASK_003`/`TASK_004` models, migrations, or test files. See Decision 1.

## 3. Decisions

### Decision 1 — `Listing.observed_at` and `price_kind` are **nullable**, against the original design

The plan called for `observed_at` non-null. It cannot be, and the reason is a
hard rule rather than a preference.

`CLAUDE.md`: *"Acceptance criteria are failing test functions… Implementation
makes them pass without modifying them. If a test is wrong, stop and say so — do
not edit it."*

There are **11 `Listing.objects.create(...)` call sites** across three shipped
TASK_004 test files (`listings/tests/test_task_004_listings.py`,
`outcomes/tests/test_task_004_outcomes.py`,
`pricing/tests/test_task_004_pricing.py`) and **14 `RawListing.objects.create(...)`
call sites**, none of which pass these new fields. A non-null column without a
default breaks every one of them, and the only fixes are to edit frozen tests
(forbidden) or invent a default.

A default is worse than NULL here. There is no honest default for an observation
timestamp, and defaulting `price_kind` to `asking` would silently mislabel every
realised price as an asking price — the exact confusion the field exists to
prevent.

So: nullable now, with NULL meaning *"written before this field existed"*, of
which there are zero rows in practice because no resolver exists yet. **A
tightening task in phase 3 adds `NOT NULL` once a writer populates them.**
Recorded here so the deferral is deliberate and visible rather than discovered
later.

`RawListing.payload` is nullable for the same reason, and `null` vs `{}` is a
real distinction worth keeping: NULL means "no structured payload was recorded",
`{}` means "a payload was recorded and it was empty". `RawListing`'s job is not
to conflate two facts.

### Decision 2 — `occurred_at` on `RawListing`, `observed_at` on `Listing`, deliberately different names

`occurred_at` is nullable and source-stated: it is what the source said about
when the priced event happened. NULL is the honest common case for a scraped
listing that shows no date.

`observed_at` is derived and authoritative: `COALESCE(occurred_at, fetched_at)`,
written by the resolver in phase 3. It means *"the best available statement of
when this price was true"*, which is a weaker and different claim than "when the
event happened" — hence the different name.

The reason `observed_at` exists at all is a boundary, not a convenience.
`docs/00_PLANNING.md` §1 says the pricing engine "reads `Listing` and `Sku`" and
is explicitly not responsible for "reading `RawListing` directly". `PricePoint.day`
was documented as deriving from `fetched_at`, which lives on `RawListing` — so
before this task, phase 5 could not compute `day` without violating its own
boundary. `resolved_at` is not a substitute: for a backfill it is uniformly
"now".

### Decision 3 — a **third** timezone setting, and it is not env-configurable

`docs/00_PLANNING.md` §5 already anticipated this: *"Storage is UTC and display
is Asia/Manila, and the aggregation boundary is a third decision that neither
setting makes."*

Binding day-bucketing to `DISPLAY_TIME_ZONE` would mean changing a display
preference silently rebuckets every historical `PricePoint`. So bucketing gets
`AGGREGATION_TIME_ZONE`, and unlike `DISPLAY_TIME_ZONE` it is a **hardcoded
module constant, not an environment variable** — changing it invalidates all
stored history and must require a code change and a migration plan, not an env
tweak on one machine.

### Decision 4 — a date-only source value is **Manila** midnight

The 2018–present file states dates, not timestamps. "Midnight" in which zone is
a real question with an off-by-one answer. A bare date is read as Manila
midnight and stored as its UTC equivalent (16:00 the previous day), so
converting back for bucketing yields exactly the stated date.

UTC midnight also happens to work for Manila (UTC+8 → 08:00 same day), but only
by luck of the offset's sign. Manila-midnight is correct by construction.

### Decision 5 — the payload redactor and the `seller` column share one function

The obvious implementation — HMAC the `seller` column, store the verbatim CSV row
as `payload` — **defeats pseudonymisation entirely**, because the plaintext name
survives inside the payload one column over in the same immutable row.

So `redact_payload()` calls the same `pseudonymise()` that produces the column
value. The two agree because they are one code path, not because two code paths
happen to agree today. Keys the redactor does not recognise pass through
verbatim, which makes `PII_PAYLOAD_KEYS` a security boundary that must be right
on the first write.

The token is a **keyed HMAC-SHA256**, never a bare digest: the space of Filipino
names and TipidPC handles is small enough to brute-force, so an unkeyed hash is
obfuscation rather than pseudonymisation.

### Decision 6 — the key fails loudly, and can never be rotated

`SELLER_PSEUDONYM_KEY = os.environ["DJANGO_SELLER_PSEUDONYM_KEY"]` — the
subscript form, matching `SECRET_KEY` at `config/settings.py:8`, not
`.get()`-with-default. A silently-defaulted pseudonymisation key is worse than a
missing one: it produces tokens that look right and protect nothing.

**The key cannot be rotated.** Tokens live in immutable rows, so rotating
re-pseudonymises nothing already written and old/new tokens for the same
counterparty stop matching — which destroys the repeat-counterparty linkage that
was the entire reason for choosing a keyed pseudonym over simply omitting the
field. It is permanent for the life of the database and backup-critical.

### Decision 7 — `external_id` is side-qualified by the importer

One transaction becomes two `RawListing` rows (buy side, sell side). If both
carry `external_id = record_id` they differ only by `occurred_at`, so a
same-day flip makes `(source, external_id, fetched_at)` collide and the second
side is rejected as a false duplicate.

The convention is `"{record_id}:buy"` / `"{record_id}:sell"`. The *importer* that
applies it is TASK_007; this task freezes the constraint-level tests that prove
the convention is necessary and sufficient, so TASK_007 cannot quietly drop it.

### Decision 8 — `trade_side` may only accompany a realised price

A `CheckConstraint`: `trade_side IS NULL OR price_kind = 'realised'`. An asking
price has no buy/sell side — nothing has traded. The converse is deliberately
*not* enforced: a "sold for ₱X" forum capture is realised with an unknown side,
so a realised price without a side stays legal.

import pytest

    assert "os.environ" not in assignment.group(1), (

    )

    row.refresh_from_db()

    assert row.fetched_at is not None

    row = _raw(source, payload=payload)
    row.refresh_from_db()
    assert row.payload == payload


def test_payload_null_and_empty_dict_are_distinguishable(source):
    """NULL payload ('none recorded') and {} ('recorded and empty') are different facts and stay different."""
    absent = _raw(source, payload=None)
    empty = _raw(source, payload={})
    absent.refresh_from_db()
    empty.refresh_from_db()
    assert absent.payload is None
    assert empty.payload == {}


# --- pseudonymisation -------------------------------------------------------

def test_pseudonymise_is_stable_for_the_same_counterparty():
    """The same counterparty yields the same token, which is what makes repeat-counterparty linkage possible."""
    from ingestion.pseudonymise import pseudonymise

    assert pseudonymise("Juan Dela Cruz") == pseudonymise("Juan Dela Cruz")
    assert pseudonymise("Juan Dela Cruz") != pseudonymise("Maria Santos")


def test_pseudonymise_is_keyed_not_a_bare_digest():
    """The token is an HMAC under a secret key, never a bare SHA-256 of the plaintext, which would be brute-forceable."""
    from ingestion.pseudonymise import pseudonymise

    plaintext = "Juan Dela Cruz"
    assert pseudonymise(plaintext) != hashlib.sha256(plaintext.encode()).hexdigest()


def test_pseudonymise_changes_with_the_key(monkeypatch):
    """A different key produces a different token — proving the key is actually an input."""
    from django.test import override_settings
    from ingestion.pseudonymise import pseudonymise

    with override_settings(SELLER_PSEUDONYM_KEY="key-one"):
        first = pseudonymise("Juan Dela Cruz")
    with override_settings(SELLER_PSEUDONYM_KEY="key-two"):
        second = pseudonymise("Juan Dela Cruz")
    assert first != second


def test_redactor_replaces_pii_keys_and_passes_everything_else_through():
    """redact_payload pseudonymises known PII keys and leaves every other key verbatim."""
    from ingestion.pseudonymise import pseudonymise, redact_payload

    redacted = redact_payload(
        {"seller": "Juan Dela Cruz", "item": "RTX 4070", "price": "15500"}
    )
    assert redacted["seller"] == pseudonymise("Juan Dela Cruz")
    assert redacted["item"] == "RTX 4070"
    assert redacted["price"] == "15500"


def test_redacted_payload_token_is_identical_to_the_seller_column_token(source):
    """The payload's counterparty token and the seller column's token are the same value from the same function — not two independently derived values that merely agree today."""
    from ingestion.pseudonymise import pseudonymise, redact_payload

    name = "Juan Dela Cruz"
    row = _raw(
        source,
        seller=pseudonymise(name),
        payload=redact_payload({"seller": name, "item": "RTX 4070"}),
    )
    row.refresh_from_db()
    assert row.payload["seller"] == row.seller
    assert row.seller == pseudonymise(name)


def test_plaintext_counterparty_name_appears_nowhere_in_the_persisted_row(source):
    """The security property: after a pseudonymised write, the plaintext name is absent from every column of the stored row, payload included."""
    from ingestion.pseudonymise import pseudonymise, redact_payload

    name = "Juan Dela Cruz"
    row = _raw(
        source,
        seller=pseudonymise(name),
        payload=redact_payload({"seller": name, "item": "RTX 4070", "notes": "meetup QC"}),
    )
    row.refresh_from_db()

    serialised = json.dumps(
        {
            "raw_title": row.raw_title,
            "raw_price_text": row.raw_price_text,
            "url": row.url,
            "seller": row.seller,
            "external_id": row.external_id,
            "payload": row.payload,

        default=str,
    )
    assert name not in serialised
    assert name.lower() not in serialised.lower()

def test_side_qualified_external_ids_let_both_sides_of_a_same_day_transaction_persist(source):
    """A transaction bought and sold on the same day writes two rows, because ':buy' and ':sell' make them distinct by construction."""
    from ingestion.models import RawListing

    now = timezone.now()
    occurred = datetime(2019, 3, 4, 16, 0, tzinfo=dt_timezone.utc)
    _raw(source, external_id="REC-001:buy", fetched_at=now, occurred_at=occurred)
    _raw(source, external_id="REC-001:sell", fetched_at=now, occurred_at=occurred)
    assert RawListing.objects.filter(source=source).count() == 2


def test_unqualified_external_id_collides_for_a_same_day_transaction(source):
    """The failure the suffix exists to prevent: without it, the second side of a same-day transaction is rejected as a false duplicate."""
    now = timezone.now()
    _raw(source, external_id="REC-001", fetched_at=now)
    with pytest.raises(IntegrityError):
        with transaction.atomic():
            _raw(source, external_id="REC-001", fetched_at=now)


def test_side_qualified_external_id_still_rejects_a_true_duplicate(source):
    """Suffixing must not disable idempotency: re-importing the same side of the same record at the same fetch time still collides."""
    now = timezone.now()
    _raw(source, external_id="REC-001:buy", fetched_at=now)
    with pytest.raises(IntegrityError):
        with transaction.atomic():
            _raw(source, external_id="REC-001:buy", fetched_at=now)
