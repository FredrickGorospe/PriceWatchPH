# TASK_002 — SOURCES.md doc pairing + Source model

## 1. Scope

Goal: `SOURCES.md` and a new `Source` model are paired — every source
documented in `SOURCES.md` has a corresponding representation strategy in the
database, `terms_notes` carries the ToS/robots.txt finding out of prose and
into a place ingestion code can read it, and only the sources currently marked
`APPROVED` in `SOURCES.md` exist as `Source` rows.

**Out of scope for this task** — do not touch, do not scaffold, do not
anticipate:

- Any `Source` row for eBay, TipidPC, Carousell PH, or Philippine retailer list
  prices — all four remain `UNDER REVIEW` in `SOURCES.md` and must not be
  seeded as if live.
- The `is_active` field from `docs/00_PLANNING.md`'s original Source table —
  deferred to a later task; every `Source` created here is implicitly active
  since none are paused yet.
- Ingestion code (`ebay_client`, `tipidpc_scraper`, `manual_capture`,
  `retailer_prices`) that would actually read `Source.rate_limit` or
  `Source.terms_notes` to throttle or gate a request — phase 1.
- `Sku`, `SkuAlias`, `RawListing`, `Listing`, `PricePoint`, `DealFlag`,
  `Outcome` and their migrations — TASK_003/TASK_004.
- DRF, the scheduler, management commands.

## 3. Acceptance criteria

Acceptance tests are written and approved here, before any implementation
exists, per the workflow in `CLAUDE.md`. All six currently fail — by
collection/import error, since `sources` does not exist yet. That is the
required state. Implementation must make them pass without modifying them; if
a test turns out to be wrong, stop and say so rather than editing it.

Two decisions precede the tests, because each commits the implementation to a
shape the tests then lock in.

**Decision 1 — `rate_limit` semantics, and nullability.** `docs/00_PLANNING.md`
left `rate_limit` as "integer (+ unit)" without settling interval-vs-window.
This task picks: **`rate_limit` is a `PositiveIntegerField` holding the
minimum whole seconds between requests to that source** — not a
requests-per-window count. Reasoning: ingestion here runs from cron as a
single process invoking one management command per source, not a continuous
consumer; "wait at least N seconds since the last request" needs only a
`last_successful_fetch`-style timestamp to enforce, while a requests-per-window
scheme needs a rolling count the system has no other reason to track. The
simpler shape matches "no broker, cron plus a management command."

**`rate_limit` is nullable.** The two currently-approved sources
(`personal_records`, `manual_capture`) involve no automated fetching at all,
so there is nothing for any number of seconds to describe. An earlier draft
of this task set both seed rows to `rate_limit=1` as a "nominal" value; that
was wrong, not conservative — `1` reads to any later reader (including a
future review) as a verified, real rate limit, when no such thing exists for
a manually-entered source. `docs/00_PLANNING.md` never marking this field
nullable was a gap in that planning document, not a decision against
nullability, and this task closes that gap rather than violating the spec:
`rate_limit` is `null=True`, and both seed rows use `rate_limit=None`. The
`> 0` constraint from `docs/00_PLANNING.md` (`rate_limit > 0`, DB-level
`CheckConstraint`) is unaffected by this — standard SQL `CHECK` constraints
are satisfied by `NULL` (the expression evaluates to unknown, not `FALSE`),
so a nullable column with this constraint still rejects `0` and negative
values while allowing "no cadence exists."

**Decision 2 — SOURCES.md ↔ `Source.name` mapping.** The doc-pairing test
below parses `SOURCES.md` for `## N. <Heading>` sections and each one's
`**Status:**` line, then checks the `APPROVED` set against `Source` rows. A
heading like "My own 2018–present buy/sell records, entered manually" is not a
usable database natural key (`docs/00_PLANNING.md` calls `Source.name` "the
natural key used in management-command arguments and logs"), so the test
hardcodes an explicit heading→slug mapping for all six sources rather than
auto-slugifying — auto-slugification would just relocate the ambiguity into
unstated slugify rules. This mapping is the seam: adding a seventh source, or
changing a heading's wording, means updating this dict by hand, deliberately,
rather than the test silently adapting.

The exact content of `sources/tests/test_task_002_sources.py`:

```python
import re
from pathlib import Path

import pytest
from django.db import IntegrityError, transaction

REPO_ROOT = Path(__file__).resolve().parent.parent.parent

# Deliberately explicit, not auto-slugified — see Decision 2 in
# tasks/TASK_002_SOURCES.md. Every heading in SOURCES.md must appear here,
# whether or not that source is currently approved.
SOURCE_NAME_BY_HEADING = {
    "eBay API": "ebay_api",
    "My own 2018–present buy/sell records, entered manually": "personal_records",
    "TipidPC": "tipidpc",
    "Carousell PH": "carousell_ph",
    'Philippine retailer list prices (the "new" depreciation anchor)': "retailer_list_prices",
    "Manual paste-a-listing capture": "manual_capture",
}


def _parse_sources_md_statuses():
    """Return {heading: status} for every numbered source section in SOURCES.md."""
    text = (REPO_ROOT / "SOURCES.md").read_text()
    statuses = {}
    for section in re.split(r"^## ", text, flags=re.MULTILINE)[1:]:
        heading_line, _, body = section.partition("\n")
        heading_match = re.match(r"\d+\.\s*(.+)", heading_line.strip())
        if not heading_match:
            continue  # "Excluded sources" has no leading number
        status_match = re.search(r"\*\*Status:\*\*\s*(.+)", body)
        statuses[heading_match.group(1).strip()] = status_match.group(1).strip()
    return statuses


def test_source_can_be_created_with_all_fields_and_null_last_successful_fetch(db):
    """A Source can be created with base_url, terms_notes, a positive rate_limit, and a null last_successful_fetch."""
    from sources.models import Source

    source = Source.objects.create(
        name="test_full_source",
        base_url="https://example.invalid/api",
        terms_notes="test fixture terms notes",
        rate_limit=30,
    )
    source.refresh_from_db()
    assert source.last_successful_fetch is None


def test_source_name_must_be_unique(db):
    """The database rejects a second Source row with a name that already exists."""
    from sources.models import Source

    Source.objects.create(
        name="test_duplicate_source",
        base_url="https://example.invalid",
        terms_notes="test fixture",
        rate_limit=60,
    )
    with pytest.raises(IntegrityError):
        with transaction.atomic():
            Source.objects.create(
                name="test_duplicate_source",
                base_url="https://example.invalid",
                terms_notes="test fixture",
                rate_limit=60,
            )


def test_source_rate_limit_must_be_positive(db):
    """The database rejects a Source row with rate_limit <= 0."""
    from sources.models import Source

    with pytest.raises(IntegrityError):
        with transaction.atomic():
            Source.objects.create(
                name="test_nonpositive_rate_limit",
                base_url="https://example.invalid",
                terms_notes="test fixture",
                rate_limit=0,
            )


def test_source_rate_limit_can_be_null(db):
    """A Source with no automated fetching cadence can leave rate_limit null."""
    from sources.models import Source

    source = Source.objects.create(
        name="test_source_no_automated_cadence",
        base_url="",
        terms_notes="test fixture: no automated fetching to rate-limit",
        rate_limit=None,
    )
    source.refresh_from_db()
    assert source.rate_limit is None


def test_source_terms_notes_is_required(db):
    """The database rejects a Source row whose terms_notes is empty."""
    from sources.models import Source

    with pytest.raises(IntegrityError):
        with transaction.atomic():
            Source.objects.create(
                name="test_missing_terms_notes",
                base_url="https://example.invalid",
                terms_notes="",
                rate_limit=60,
            )


def test_approved_sources_in_sources_md_have_matching_source_rows(db):
    """Every source marked APPROVED in SOURCES.md, and no other, has a matching Source row with a null rate_limit."""
    from sources.models import Source

    statuses = _parse_sources_md_statuses()
    approved_headings = {h for h, s in statuses.items() if s == "APPROVED"}
    expected_names = {SOURCE_NAME_BY_HEADING[h] for h in approved_headings}
    actual_names = set(Source.objects.values_list("name", flat=True))
    assert actual_names == expected_names, (
        f"Source rows {actual_names!r} do not match SOURCES.md's APPROVED set {expected_names!r}"
    )
    assert all(
        rate_limit is None
        for rate_limit in Source.objects.filter(
            name__in=expected_names
        ).values_list("rate_limit", flat=True)
    ), "seeded sources have no automated fetching cadence, so rate_limit must be null"
```

`sources/models.py`'s shape, stated so the task's intent is unambiguous:

```python
from django.db import models
from django.db.models import Q


class Source(models.Model):
    name = models.CharField(max_length=100, unique=True)
    base_url = models.TextField(blank=True, default="")
    terms_notes = models.TextField()
    # Null means "no automated fetching cadence exists to describe" — not
    # unlimited and not merely unset. docs/00_PLANNING.md never marked this
    # field nullable; that was a gap in the spec, closed here, not a
    # violation of it. See Decision 1 in this task file.
    rate_limit = models.PositiveIntegerField(null=True, blank=True)
    last_successful_fetch = models.DateTimeField(null=True, blank=True)

    class Meta:
        constraints = [
            models.CheckConstraint(
                condition=Q(rate_limit__gt=0),
                name="source_rate_limit_positive",
            ),
            models.CheckConstraint(
                condition=~Q(terms_notes=""),
                name="source_terms_notes_not_blank",
            ),
        ]

    def __str__(self):
        return self.name
```

`CheckConstraint`'s `condition=` keyword (not `check=`) was verified against
Django 5.2.16's actual source — the version pinned in `requirements.txt` since
TASK_001 — rather than assumed; `check=` still works but emits
`RemovedInDjango60Warning`.

  — `Source` uses the same `django.db.backends.postgresql` connection
  TASK_001 already configured; no new engine choice is introduced here.
- **No Celery, no Redis, no message broker. Scheduling is cron plus a Django
  management command.** Not exercised — nothing like that is introduced.
- **Money is always Decimal. Never float. Never FloatField.** Not applicable
  — `Source` has no money field; `rate_limit` is a count of seconds, not
  currency.
- **RawListing is immutable after write.** Not applicable — `RawListing`
  doesn't exist yet.
- **Facebook Marketplace is out of scope permanently.** Directly relevant and
  complied with: Facebook Marketplace has no `Source` row, and the seed
  migration seeds only the two currently-`APPROVED` sources.
- **Python 3.12, Django 5.2, DRF. No framework substitutions.** Complied with
  — the new app uses the same Django 5.2 installation pinned in TASK_001; DRF
  remains uninstalled, consistent with there being no API surface for
  `Source` either.
- **Timestamps are stored in UTC, USE_TZ is True. Display timezone is
  Asia/Manila and is a separate setting, never the storage timezone.**
  Complied with — `last_successful_fetch` is a plain `DateTimeField` under the
  already-`True` `USE_TZ`, so Django stores it timezone-aware in UTC by
  default; no new timezone setting is introduced.
- **No frontend framework before phase 6. Django admin is the UI until
  then.** Complied with — `sources/admin.py` registers `Source` for the admin
  (plain `ModelAdmin`, no custom views/actions), which is exactly what "admin
  is the UI" means at this phase, not a violation of it.
- **Secrets come from environment variables. Never hardcoded, never
  committed.** Not applicable — `Source` holds no secrets; `base_url` and
  `terms_notes` are not credentials.
